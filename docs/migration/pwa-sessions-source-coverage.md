# PWALIST2 source coverage

This is the source-to-Ferretry map for the four kteam sources assigned to
PWALIST2. Like the AUDITTR map it is a **capability** map rather than a filename
comparison: the migration split each kteam component into a pure decision
module, a rendered surface, and a daemon-scoped composition.

It also draws a line the filename survey cannot. A source file is only declared
PORTED when every capability inside it landed. Capabilities that the source file
merely _sat next to_ — the store it read, the route it called, the popover it
opened — are recorded as **adjacent gaps**: real, named, and explicitly not
claimed. Where an adjacent gap lives inside the assigned file, the file itself
is NOT PORTED.

_computes_ is ported and daemon-scoped; what is missing is a panel it renders
inline and two feeds it read. Calling it PORTED-AS would let a reader conclude a
search gesture returns transcript matches and that the dashboard is live, and
neither is true.

## The composer popover gap, stated plainly

The engine is ported and its controller is wired into `composer.tsx`. Nothing
renders a list: there is no composer `role="listbox"` anywhere in
`packages/pwa/src`. That combination is worse than either half alone, and this
declaration exists so no reader mistakes a green engine suite for a working
composer.

What it costs today, reachable offline on the first keystroke:

- Typing `/` opens the list. The slash provider's `initialCandidates` answers
  synchronously with the built-in commands, so there is an active candidate and
  a `ready` status — all invisible.
- `composer.tsx` consults `handleKeyDown` before its own Enter-to-send branch,
  so Enter accepts the invisible candidate instead of sending the message.
  ArrowUp/ArrowDown/Escape are swallowed the same way.
- `aria-controls` and `aria-activedescendant` name an element id that is never
  in the DOM, and the click-outside guard's `getElementById` is always null.

The fix is one component — `ui/src/components/ComposerAutocomplete.tsx` →
`packages/pwa/src/components/composer-autocomplete-popover.tsx`, rendered from
`composer.tsx`. Everything it needs the controller already produces and nothing
consumes: `provider.legend`, `contextLabel`, `notice`, `error`, and each
candidate's `group`, `badge`, `disabled` and `disabledReason`.
`src/features/analytics/analytics-query-autocomplete.tsx` is the in-repo
precedent for the listbox/option shape.

## What the adjacent gaps have in common

Five of the six are one decision away from each other:

| Gap                            | Blocked on                                                                                         |
| ------------------------------ | -------------------------------------------------------------------------------------------------- |
| fleet-event reconciliation     | browser ticket issuance, then a reconcile path into the per-daemon slice. The daemon route exists. |
| warden-verdict feed            | a protocol schema first; the renderer is already there.                                            |
| pull-to-palette                | the palette host — app assembly.                                                                   |
| a host for the browser surface | `renderSurface` — app assembly.                                                                    |
| transcript render hold         | the transcript unit, independent of all of the above.                                              |
| the composer popover           | nothing. It is one unassigned component.                                                           |

The transcript-search route is the odd one out: it needs daemon work
(`IFyApiClient` has no search) before any PWA panel can honestly exist.
