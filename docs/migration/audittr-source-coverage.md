# AUDITTR source coverage

This is the source-to-Ferretry map for the transcript and analytics audit. It is
deliberately a capability map rather than a filename comparison: the migration
split each kteam monolith into parser, source, analytics, storage, and mounting
modules.

## Blocking chain — the root cause is closed

The slice this section called for has landed. `SessionConfig.transcript` records
the wrapper-resolved harness home and the harness session identity at creation,
Claude's path is derived from an id the daemon mints and passes on the argv, and
Codex is discovered only against a pre-launch baseline plus an injected
correlation token. `DaemonWorld.transcripts` is called, and its entry is gone
from `scripts/validate/invocation-blocked.txt`.

What that unblocked, and what each still needs:

| Downstream capability            | State                                                                                                                                                                                                                                                                                                                        |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| migration tool inventory         | **DONE.** The preflight joins its open tool ids against the session's own transcript. An open tool is named and verdicted instead of being classified `unknown` and refusing the migration.                                                                                                                                  |
| `state.lastTranscriptAt`         | **STILL UNWRITTEN.** The value is now derivable — a transcript read yields event timestamps — but there is no producer to write it on a schedule. It needs a liveness pass that polls each live session, and no such pass is mounted; the warden detector that reads it is unmounted for the same reason.                    |
| learning extraction              | **HALF FREE.** `extractSession`'s `records` can be supplied. Its `inbox` cannot: there is no send ledger for a mounted session, and for an AUTO session `humanMessages` and `teammateSteers` are computed from the inbox alone — so a digest built now would report zero human signal as a measurement rather than as a gap. |
| analytics source materialization | **STILL OPEN**, but no longer for the reason recorded above: a source can be enrolled now. What is missing is the SQLite table, the per-source cursor and the backfill pass.                                                                                                                                                 |

The next coherent slice is the FOLLOWER: `TranscriptSource.follow` is ported and
nothing subscribes. A mounted follower per live session is what would write
`lastTranscriptAt`, feed usage ingestion an exact source, and give the Codex
resolver a natural retry point for a rollout that has not been flushed yet.
