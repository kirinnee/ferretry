# PR #5 — complete task board membership lifecycle
# BLOCKED ON AN ADAPTER THAT DOES NOT EXIST. Every service here is a pure reducer over a
# TaskBoardRepository whose `transaction` must be atomic, plus a TaskBoardCredentialIssuer that mints
# and hashes board capabilities, plus a TaskBoardSessionDirectory. There is no src/adapters/task-boards
# at all, so mounting this means PORTING the persistence and the credential minting — not wiring —
# and a capability store built by guesswork is a security boundary built by guesswork.
#
# RE-CHECKED by the second wiring unit, and the blocker is narrower and harder than "no adapter": the
# repository IS a snapshot the file-store pattern here already fits, but every grant in it is keyed on
# a `sessionCapabilityHash` — "hash of the daemon-owned session credential" — and no such credential
# exists anywhere in this daemon. `sessionCapabilityHash` appears in no file outside this directory: a
# session authenticates with the shared admin token plus the `x-ferretry-session-id` header, which is
# an ATTRIBUTION, not a secret only that session holds. Mounting boards therefore means first minting
# a per-session credential at session start — which is not mounted — and every grant, invitation proof
# and child grant hangs off it. That is the security boundary, and it cannot be invented here.
#
# RE-CHECKED by the fourth wiring unit now that session start IS mounted, and the blocker moved rather
# than fell: minting the credential is no longer the binding constraint, DELIVERING it is. The CLI
# reads it from the environment and the launch path cannot set one — see "THERE IS NO WAY TO HAND A
# SESSION A SECRET" in the header above. Until that seam exists, every peer-scoped board command in
# `fy task-board` refuses before it sends, so the whole surface would be operator-only.
#
# THAT SEAM NOW EXISTS, and the "no way to hand a session a secret" blocker above is SPENT — read it
# as history rather than as the current state. `TmuxLaunch` carries an `env`, `newSessionArguments`
# emits `-e NAME=VALUE` before the command word, `TmuxSessionLifecycleLauncher` reads the session's
# environment at every launch, and `SessionLifecycleService.create` mints a 256-bit credential for
# EVERY session: the SHA-256 goes on the record as `sessionCapabilityHash` — which is the exact field
# every grant, invitation proof and child grant here is keyed on — and the plaintext goes to one 0600
# file in the session's directory, delivered to the pane as `FY_SESSION_BOARD_CAPABILITY`. It is
# deliberately absent from the session document, because that document is projected by the API.
#
# WHAT IS ACTUALLY LEFT IS A PORT OF FOUR ADAPTERS AND ONE UNDECIDED SECURITY QUESTION. The four are
# mechanical and the port interfaces in `types.ts` specify them completely: `TaskBoardRepository`
# (a snapshot with an atomic `transaction` — the `FileTaskStore` + `KeyedSerialExecutor` pattern in
# `adapters/tasks` already fits it), `TaskBoardCredentialIssuer` (`id`, `capability`, `hash` — the
# same shape as `NodeSessionCredentialIssuer`), `TaskBoardClock`, and a `TaskBoardSessionDirectory`
# over the session index, which can now answer `sessionCapabilityHash` for every session. The route
# surface is fully known too: `packages/cli/src/adapters/tasks/fy-task-board-gateway.ts` names all
# eleven paths under `/v1/task-boards`.
#
# THE UNDECIDED QUESTION, and the reason this unit stopped rather than mounting: `fy task-board
# create`, `mark-done`, `coordinator-replace` and `revoke` authenticate with
# `FY_BOARD_ADMIN_CAPABILITY` — the OPERATOR's capability, which `board-credentials.ts` documents as
# "deliberately unavailable inside a teammate pane". Nothing in this daemon mints that secret, and
# nothing gives a human a way to read it: it is not the admin API token, and there is no operator

# PR #9 — add the callsign name pool, managed worktrees, and the Git adapter
# The callsign POOL and the ALLOCATOR are both mounted now. The allocator's blocker was recorded as
# "an atomic claim store and a mounted session start", and the unit that mounted session start built
# the store it needed: `FileNameClaimStore` keeps the reservation ledger in the state home, serialized
# through one executor keyed on that file, which is atomic across concurrent requests because only one
# daemon can hold the state home at all — the lifetime lock is what stops a second one serving.
# `POST /v1/sessions` claims the callsign BEFORE it writes the session document, so `--teammate` on a
# name another session answers to is a 409 rather than two sessions one callsign resolves to.
#
# The WORKTREE barrel is a different shape of gap, and worth stating exactly: every module beneath it
# — parser, policy, ports, types — is already reachable, because the Git adapters import them
# directly. The barrel has no importer because no MOUNT exists to be the one caller that wants the
# domain as a whole. There cannot be one yet: `ManagedWorktreeAdapter` is constructed in the world but
# nothing calls it, and the routes the CLI already speaks (`/v1/worktrees`, `/v1/worktrees/remove`)
# need a registry of managed worktrees to serve. A `ManagedWorktree` record carries an ownership
# token, a creation instant and whether its branch pre-existed — none of it derivable from Git — so it
# must be PERSISTED when the worktree is created, by a session start that is not mounted either. The
# barrel is left rather than deleted because it is the import the mount will take, not dead weight.
#
# RE-CHECKED by the second wiring unit against the wire shapes the CLI parses, because a READ-ONLY
# worktree mount looked like a way in. It is not. `ManagedWorktreeView` demands createdAt, initialHead,
# branchPreexisted, ownerSessionId, ownerActive and sharedWith, and Git knows none of them. Even the
# cheapest route, the removal CHECK at `/v1/worktrees/removal`, takes a `CheckManagedWorktreeRemovalInput`

# on its own. The start is mounted and it still cannot write this registry: `StartSessionRequest` has
# NO worktree or branch field of any kind, and neither does the CLI's own start. So there is nothing a
