# header; that sentence is now history.
#
# THE DISPLAY IS OWNED, NOT INHERITED, which was the sharpening the second wiring unit recorded and it
# was right. `display()` is not "resolve $DISPLAY": the operator's own desktop is what $DISPLAY names,
# and this window's whole purpose is to publish a screen to whoever holds the VNC password. `XvfbDisplay`
# starts an Xvfb with `-displayfd`, which takes a free display and reports the number it took ONCE IT IS
# ACCEPTING CONNECTIONS — so one mechanism answers both "which display" and "is it up", and there is no
# window in which two daemons on one host choose the same number. It is created once and released by
# `cleanups`, because the runtime contract has no per-window release hook to hang it on.
#
# WHAT MOUNTING FOUND, which no unit test had reached:
#   * A `confirm` WITH NO WINDOW OPEN is classified `launch_failed` by the domain, not `bad_request`.
#     The mount passes the domain's split through rather than re-deciding it, so that answers 503 —
#     which is the honest reading: it is a statement about the window, not about the request.
#   * AN UNUSABLE DISPLAY ANNOUNCEMENT AND A DEAD Xvfb ARE DIFFERENT FAILURES, and the stream closing
#     wins the race against the exit being observed. Readiness is therefore a USABLE NUMBER rather than
#     merely an answer, so an Xvfb that died reports its exit status instead of "did not report a
#     display number" — the diagnostic an operator can act on.
#
