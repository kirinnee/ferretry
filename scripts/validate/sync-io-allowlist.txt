# THE SYNCHRONOUS-IO LEDGER — every blocking file call or `spawnSync` left in daemon code, and why.
#
# Checked by scripts/validate/no-sync-io.sh. One line per file:
#
#   <count> <path>  # <class>: <why it may block the thread it runs on>
#
# A use is a call or a reference handed on (`exists: existsSync`), counted by parsing (no-sync-io.ts).
# The count is EXACT, both ways: a new call fails the gate, and so does a removed one until its line is lowered,
# so this file is always the true inventory. The daemon's main thread answers every client; a synchronous call
# there holds all of them for as long as the disk takes (a saturated disk measured 38 s for one fsync).
#
# Classes:
#   boot     runs once while the daemon starts, before it serves (a wedge there must be visible in order)
#   cli      a `fyd` subcommand's own process (`fyd --check`, `fyd config`), never the serving daemon
#   worker   runs on its own thread, never the main loop
#   wrapper  instrumentation that only passes a caller's own sync call through; counted where the caller is
#   pipe     closes a pipe descriptor, which never waits on a disk
#   bracket  must not yield: a held folder is the process's working directory for exactly this one call
#   gap      ON A REQUEST OR TIMER PATH of the serving daemon. Each is a declared debt to move off the loop.
#
# Lowering a count is always welcome. Raising one, or adding a file, needs the same reasoning in review.

# Ferretry 5.0 starts with no blocking call in any daemon half or the kernel host. A port that carries one over
# from 4.x (packages/daemon/bin/fyd.ts, the browser and tunnel adapters, the fleet descriptor brackets) adds its
# line here, under its new path, with the same reasoning.

1 packages/core/kernel/host/fyd.ts  # gap: the daemon log sink appends each line synchronously, so a slow disk holds the loop; move to a buffered async writer
2 packages/core/kernel/host/state/home-lock.ts  # boot: takes the home lock (creates run/, sets its mode) once while the daemon starts, before it serves
1 packages/core/kernel/host/adapters/launch-guard.ts  # boot: resolves the home and the temporary folders through links once while the daemon starts, before it serves, to decide the launch guard
4 packages/core/kernel/host/state/sqlite-store.ts  # boot: opens a plugin's database (directory, mode, existence, removal of a refused file) while plugins start, before the daemon serves; bun:sqlite itself is synchronous
9 packages/core/kernel/host/adapters/pinned/posix-session-root-pinner.ts  # bracket: pins a session root by descriptor
2 packages/core/kernel/host/adapters/pinned/working-directory.ts  # bracket: the descriptor of / the bracket falls back to
2 packages/core/kernel/host/adapters/update-host.ts  # gap: the update child's log file, when an update is applied
3 packages/core/ferrets/daemon/adapters/session/observer/worker-children.ts  # worker: a session worker replaces its own Bun.spawnSync to count children
1 packages/plugins/browsers/daemon/worker/control/adapters/login-runtime.ts  # gap: the sign-in window finds Chrome with existsSync when it opens (today's), on a request; move to an async look
3 packages/plugins/browsers/daemon/adapters/host.ts  # gap: Chrome's lookup at each launch (existsSync, today's) and the worker program found beside the daemon at build (realpathSync/existsSync, today's boot lookup); move to async looks
1 packages/plugins/browsers/daemon/worker/adapters/main.ts  # worker: the browser worker is its own process (lead decision, port-browsers r1); closes fd 3 of Chrome's pipe, never the daemon's loop
