# PWA state that is deliberately NOT keyed by daemon, and daemon-scoped caches the connection
# registry deliberately does not hold.
#
# Enforced by scripts/validate/daemon-scope.sh. Read that script's header for what each pass means
# and why the rule exists; this file is only the list of reviewed exceptions to it.
#
# Rules the gate enforces on this file:
#   * one line per exception, `<retain|access|invalidate> <exact target> # <reason>` — no globs, so
#     silencing a NEW finding always costs a visible, reviewable line in the diff;
#   * the reason is required, and it must say why one daemon's data cannot be read as another's —
#     "not daemon data" and "the owner clears it" are the only two shapes of answer that exist;
#   * an entry that no longer describes a finding is a hard failure. Delete it in the change that
#     fixed it: a stale exemption is a silencer aimed at the next bug, not documentation of an old
#     one.
#
# THIS IS NOT AN EXEMPTION POLICY. Every `invalidate` line below is a store that keeps serving an
# unpaired daemon's records unless something else clears it, and each one names the something else.
# If you cannot name it, you have found the bug this gate was written for.

# RETAIN — module-scope state that holds no daemon-owned data
#
# The pass asks one question of a module-level binding: could this remember something a daemon
# said? A reader preference, a DOM layering stack, a pub-sub listener set and a component registry
# all answer no, and answer it the same way — the value would be identical no matter which daemon
# the reader is paired to, or how many.

retain packages/pwa/src/lib/agenda-deep-link.ts:pending # the one #agenda/<id> link this page was opened with, captured once and cleared when used. It names a session id the reader's own browser holds; no daemon record is in it, and it is resolved against the paired daemons afterwards.
retain packages/pwa/src/lib/agenda-deep-link.ts:listeners # the hook callbacks waiting for that one link; identities of mounted components, never daemon records.
retain packages/pwa/src/hooks/use-density.ts:firstLoadDefault # the reader's density, resolved once from a pointer media query. It describes the device holding the browser, which every paired daemon shares.
retain packages/pwa/src/hooks/use-dialog-focus.ts:ESCAPE_LAYERS # the Escape-key layering stack, holding opaque DOM tokens in arrival order. Entries are identities of mounted overlays, never daemon records.
retain packages/pwa/src/lib/theme-fonts.ts:preloaded # the font files already hinted in one document's head. It describes this page's own <link> elements, never a daemon's records, and a font file is the same whichever daemon is paired.
retain packages/pwa/src/hooks/use-project-scope.ts:browserNavigation # the lazily built window-navigation adapter. A stable identity is required because it is an effect dependency; it wraps `window` and reads nothing from a daemon.

retain packages/pwa/src/lib/pin-bridge.ts:foreground # holds a DaemonSessionScope and nothing else, and compares by daemonSessionKey. It IS the daemon scope the rest of the bridge is keyed by; there is no second thing here to key.
retain packages/pwa/src/lib/relay-carrier.ts:livenessChecks # a WeakMap from a live RelayClientSession object to its own ping function. retain packages/pwa/src/lib/trusted-types.ts:shared # the page's two Trusted Types policies, created once because the browser refuses a second policy of a name. They hold rules, never a daemon record, and every paired daemon is held to the same ones.

# INVALIDATE — daemon-scoped caches the connection registry does not hold, and what clears them
#
# Two honest reasons appear below and no third one is acceptable. Either an OWNER holds the cache
# and forwards clearDaemon to it, or the surface is NOT MOUNTED and its line must be deleted by the
# change that mounts it. "It is keyed by daemon so staleness is harmless" is not on that list:
# daemon ids are DURABLE ACROSS A RE-PAIR (see lib/daemon-connection.ts), so the next pairing with
# the same id reads the last one's records back.

invalidate DaemonSessionCache # the keyed-cache PRIMITIVE, not a cache. Stores are built out of it and are registered themselves; registering the class would be registering the concept.
invalidate DaemonUsageIndex # owned by DaemonUsageStore, which IS registered and forwards clearDaemon to it (lib/usage-store.ts:226).
invalidate DaemonAgendaStore # owned by DaemonAgendaClient, which forwards clearDaemon to it (lib/agenda-client.ts:188).
invalidate DaemonPinStore # owned by DaemonPinClient, which forwards clearDaemon to it (lib/pin-client.ts:165).
invalidate DaemonNotificationLedger # cleared by its own watcher: startNotificationWatch diffs the daemon set each tick and calls clearDaemon for every daemon that left the snapshot (lib/notification-ledger.ts:278). It is in-memory only and never outlives the watch.
invalidate DaemonAttachmentBlobCache # a per-mount useRef in attachment-gallery.tsx, disposed with the component. Every entry carries its own daemonId and clearDaemon filters on it, so no cross-daemon read is reachable; the registry cannot hold a cache that is created per mount.

# GAPS. Each of these is a daemon-scoped store that NOTHING under packages/pwa/src constructs — the
# surface is not mounted, so there is no instance to register. Delete the line in the PR that mounts
# it, and add the store to the `caches:` array in lib/store.tsx in the same change.
invalidate DaemonRuntimeModelCatalogStore # unmounted: no construction site in packages/pwa/src. runtime-controls.tsx names the type as the port it wants; nothing supplies one.
