# Composition-root fields that are constructed but CANNOT yet be called, with the blocker.
#
# Enforced by scripts/validate/composition-invocation.sh. This is not an exemption policy: an entry
# here is a capability the product does not have, and the line stays until the blocker is gone.
#
# Rules the gate enforces on this file:
#   * one exact `Interface.field` per line — no globs, so silencing a NEW field always costs a
#     visible, reviewable line in the diff;
#   * every entry carries a trailing '# <blocker>' stating what is missing, as a checkable fact;
#   * an entry that has become called is a hard failure — delete it in the PR that wires it.
#
# Do not add a line because wiring is inconvenient. Add it only when calling the field would be
# WRONG or IMPOSSIBLE, and say which.

DaemonWorld.worktrees # ManagedWorktreeAdapter cannot answer the routes the CLI already speaks. /v1/worktrees and /v1/worktrees/remove need a REGISTRY of managed worktrees, and ManagedWorktreeView demands createdAt, initialHead, branchPreexisted, ownerSessionId, ownerActive and sharedWith — none derivable from Git, so all of it must be persisted when the worktree is created. Nothing persists it: StartSessionRequest has no worktree or branch field of any kind, and neither does `fy start`. Even the cheapest route, the removal CHECK, takes a CheckManagedWorktreeRemovalInput whose first field is the persisted ManagedWorktree itself. Same blocker as packages/daemon/src/lib/worktrees/index.ts on the reachability allowlist; both fall to the unit that designs the wire contract for a session-owned worktree.
DaemonWorld.wardenReports # nothing writes a warden report: WardenReportFileSystem declares only listFiles and readText, warden/reports is never created, and the sweep that would author one is the subsystem PR #19 is blocked on. Mounting the reader would serve an empty list forever — and pwa warden-strip renders a green ShieldCheck for an empty list, so it would assert "fleet healthy" on no evidence. Not mounting is the honest state.
DaemonWorld.browserTransport # nothing in production implements BrowserViewerHost, so connectWorker has no host to hand a session's browser to and no caller can compute the workerEntry it takes. Wiring means writing that host, not calling the field. AUDITTMUX mapped the source and found the gap is WIDER than the worker: kteam's browser-service.ts (882 lines) is the per-session lifecycle that would HOLD a BrowserViewerHost, and none of it is here — nothing decides when a session's Chrome starts, leases the profile it starts against, arbitrates the agent against the human viewer, sweeps an idle browser, or closes every agent browser so the human login window can take the profile. Its transport half IS carried (lib/browser/transport/*, lib/browser/control/*), so this field is the port of a service that does not exist. See docs/migration/surveys/tmux-browser-stt.md §2 for the symbol map. Note the source's stt-worker-client.ts is NOT the other half of this story and no longer has a Ferretry counterpart at all: it was the SPEECH worker client, and daemon-hosted recognition is deleted — dictation recognises speech in the browser now, leaving only the hosted-model enhancement route on the daemon.
