# Where the GitHub slug (`<owner>/<repo>`) is allowed to differ from the root package.json
# `repository` field. Read by scripts/validate/repo-slug.sh (the gate) and scripts/local/move-repo.sh
# (the mover); docs/runbooks/move-repo.md explains the contract.
#
# One entry per line: `<mode> <git pathspec>`. `*` matches across `/` (git's own pathspec rule).
#
#   history  A record of what was true when it was written (changelogs, migration notes, design
#            records, the validators themselves). Never rewritten, never checked.
#   fixture  Test data that names the slug as an arbitrary example (board PR links, remote parsers,
#            which are tested against `acme/ferretry` on purpose). Never rewritten, never checked.
#   follow   A test that asserts a shipped address (update URLs, tap names, onboarding commands). The
#            mover rewrites EVERY occurrence here, issue and pull-request links included, so the test
#            keeps asserting what ships. The gate does not check it: the test suite does.
#
# Everywhere else the mover rewrites only addresses (a release, clone, tap, flake or API address) and
# leaves a link to one issue or pull request alone: GitHub keeps redirecting those after a transfer.
#
# Not listed on purpose: anything a user or the product follows — Casks/, .goreleaser.yaml, install
# scripts, INSTALLATION.md, the get-started page, onboarding commands, user docs. A shipped file
# that names the slug is controlled, and a new one is controlled the moment it names it.
