[kernel: private files made outside the daemon] GAP(kernel): a private file made through the DAEMON's state port or internal roots is pinned by identity before the write returns (Access's `fy pair --open` redirect page, which holds a live pairing code, is made by the daemon for that reason: POST /v1/pair/redirect), but a file a child process makes inside a private folder (Browsers' profile, Terminals' tmux.sock, a harness-refreshed member of Logins' credentials) is pinned only at the index's next look, within 250 ms (as in v4), unless its owner asks the daemon to renew the index: the state port's `pinMade(file, name?)` (an opaque file at `pathOf`) does, and rejects `private_unpinned` when the look cannot be made. What is left: no plugin calls it yet (Browsers' profile, Terminals' tmux.sock and Logins' harness-refreshed credentials each need to call it once their child has made the file), so in that window a root call that reaches an alias of the new file (a hard link in a hard-link root, a bind mount) answers from the kept snapshot: packages/core/kernel/host/fence-guard.ts
