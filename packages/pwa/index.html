Claude + Codex.One operating system.

Ferretry is the layer that runs Claude Code and Codex as a fleet — across accounts and working directories — so you can coordinate them, move sessions between configured accounts and keep every session supervised.

It does not replace either harness. Your models, subscriptions and credentials stay underneath; Ferretry adds the shared operating environment around them.

What ships / real surfaces only

A deep system around the agents you already use.

The daemon and fy expose these operations today. Each one is built around explicit evidence, scoped state and refusal when the safe answer is unknown.

01
fy start

Start either harness where the work lives.

Choose a configured Claude or Codex account, model, mode and absolute working directory.

02
fy send

Talk to any running session.

Deliver a next turn to Claude Code or Codex immediately or through the harness’s native queue.

03
fy task / fy attention

Make the orchestration explicit.

Track tasks, dependencies, ownership, phase history and the decisions that genuinely need a human.

04
fy migrate

Move the session, not just a prompt.

Select another configured account. The daemon preserves the session id and directory, records the handoff and refuses destructive or unknown in-flight work.

Operator-triggered / target chosen explicitly
05
fy files / fy snapshot / fy attach

Inspect the work and the pane.

On Linux hosts, read descriptor-confined files and diffs without writes; capture a live screen or attach locally to the daemon-verified terminal.

Read-only files / local attach
06
fy stt

A daemon-side path for speech-to-text.

When its on-host model and runtime are available, fy stt transcribes bounded audio on the daemon. Hosted enhancement is opt-in.

Daemon-side / not browser-local
07
fy analytics

Query finished work.

Slice completed sessions by status, duration, model, account, directory and outcome.

08
warden loop / fy fleet recommend

Keep the fleet supervised.

Watch lifecycle evidence, detect suspect sessions and recommend an eligible account for new work.

The layer, not the model

Bring your accounts. Keep your data.

Ferretry supercharges Claude Code and Codex by coordinating their real command-line harnesses. Those harnesses still connect to their providers directly; Ferretry does not sit between them and their model APIs.

  1. Declare multiple account wrappers from one host-owned fleet configuration.
  2. Pair one static app with more than one reachable machine, over the network path you provide.
  3. Keep provider credentials in the account homes on those machines.

The shape of it

Your machines become the control plane.

Each daemon owns its sessions and credentials. Every browser store, request and route stays keyed to the daemon that supplied it.

  1. Run Ferretry’s daemon on a machine where Claude Code or Codex already works.
  2. Use fy fleet to declare the accounts that machine can run.
  3. Reach the daemon over your own tailnet or tunnel, then pair the static app directly to it.
